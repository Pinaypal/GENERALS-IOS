# Development Diary - October 2026

## 2026-10-10: iPad Long Session Memory Optimization & iOS Backgrounding Lifecycle Fix & ProMotion 120Hz Support

### 1. iPad Long Session Memory Management (~3 GB+ Resident Jetsam Kill)
- **Root Cause 1 (Autorelease Pool Accumulation)**:
  In `SDL3GameEngine::update()` / `GameEngine::execute()`, the game runs a tight C++ main loop on the main thread that never yields control back to `CFRunLoop`. Temporary Cocoa, Metal (`CAMetalDrawable`, `MTLCommandBuffer`), and CoreAudio objects allocated every frame accumulated in the thread's root `NSAutoreleasePool` without ever being drained. Over thousands of frames, resident memory exceeded ~3 GB, causing iOS Jetsam to kill the process silently.
  - **Fix**: Wrapped each frame iteration in `SDL3GameEngine::update()` with `objc_autoreleasePoolPush()` / `objc_autoreleasePoolPop()` on Apple platforms, immediately reclaiming all autoreleased objects at the end of each frame.
- **Root Cause 2 (OpenAL PCM Audio Cache Underreporting & Eviction Failure)**:
  In `Core/GameEngineDevice/Source/OpenALAudioDevice/OpenALAudioCache.cpp`, `openedAudioFile.m_fileSize` was overwritten with compressed file size from disk (`file->size()`), rather than the uncompressed decoded 16-bit PCM buffer byte size (`audioData.size()`). Consequently, `m_currentlyUsedSize` drastically underestimated memory usage (often by 10x-20x), preventing the cache from reaching `m_maxSize` and leaving unreferenced audio buffers in memory indefinitely.
  - **Fix**: Preserved the actual decoded PCM buffer size in `openedAudioFile.m_fileSize`, set `m_maxSize` to 32 MB of true PCM audio with automatic eviction of samples when `m_openCount == 0`, and added `OpenALAudioFileCache::purgeUnusedBuffers()`.
- **Root Cause 3 (Low Memory Warning Handling)**:
  Added handling for `SDL_EVENT_LOW_MEMORY` in `SDL3GameEngine::pollSDL3Events()`, invoking `TheAudio->flushUnusedAudioBuffers()` to purge unreferenced samples under OS memory pressure.
- **Root Cause 4 (DXVK Unified Memory Tuning)**:
  In `ios/config/dxvk.conf`, set `dxvk.maxChunkSize = 64` (down from 256 MB) to prevent virtual/resident memory fragmentation on unified memory iOS devices, set `d3d9.maxFrameLatency = 1`, and enabled `d3d9.memoryTrackTest = True`.

### 2. iOS Backgrounding Mid-Game Lifecycle Crash
- **Root Cause (Render Loop / Present Suspension Race)**:
  When backgrounding or multitasking, `iosLifecycleWatcher` set `s_appBackgrounded` on the UIKit delivering thread while `GameEngine::update()` was mid-frame. If `_Get_D3D_Device8()->Present()` ran after the `CAMetalLayer` was seized by iOS, MoltenVK returned `D3DERR_DEVICELOST`, causing `dx8wrapper.cpp` to call `Reset_Device()`. Recreating the swapchain on a suspended Metal surface caused fatal crashes.
  - **Fix**: Added a rendering lifecycle mutex (`s_renderLifecycleMutex`) in `SDL3GameEngine.cpp` ensuring `iosLifecycleWatcher` waits for in-flight frames to finish before iOS suspension. Exported `IOS_ShouldPauseRendering()` to `Core/Libraries/Source/WWVegas/WW3D2/dx8wrapper.cpp`, skipping `Present()` and preventing `Reset_Device()` while backgrounded or inactive.
- **Root Cause (Touch Gesture Hang on Resign Active)**:
  If a swipe-up or notification interrupted a touch gesture, `s_touch.phase` remained stuck in `DRAGGING` or `PAN`.
  - **Fix**: Implemented `resetTouchState()` in `SDL3GameEngine.cpp` to release any synthetic mouse buttons and reset touch state to `IDLE` upon `SDL_EVENT_WINDOW_FOCUS_LOST` and `SDL_EVENT_DID_ENTER_BACKGROUND`.

### 3. ProMotion 120Hz Refresh Support
- **Info.plist**: Added `<key>CADisableMinimumFrameDuration</key><true/>` alongside `CADisableMinimumFrameDurationOnPhone` to unlock high refresh display links on iPad Pro and iPhone Pro.
- **DXVK Configuration**: Configured `dxvk.maxFrameRate = 120` in `ios/config/dxvk.conf`.
- **Command Line & Engine**:
  - Moved `{ "-fps", parseFPSLimit }` to `paramsForEngineInit` in `GeneralsMD/Code/GameEngine/Source/Common/CommandLine.cpp` so `-fps` is supported in Release builds.
  - In `SDL3Main.cpp`, queried native display refresh rate via `SDL_GetCurrentDisplayMode` and injected `-fps <targetFps>` (120 FPS on ProMotion).
  - In `GeneralsMD/Code/GameEngine/Source/Common/GameEngine.cpp`, defaulted `m_framesPerSecondLimit` to 120 on iOS, while preserving deterministic 30 FPS logic simulation via the decoupled logic accumulator.
